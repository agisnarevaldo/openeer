# Openeer Domain Context

Openeer is an AI Gateway that mediates requests between client applications and AI providers, providing unified authentication, rate limiting, and usage tracking.

## Language

### Core Entities

**User**:
An authenticated human account that owns API Keys and views analytics in the Dashboard.
_Avoid_: Account, Client, Customer, Member

**Session**:
A temporary authenticated state identifying a User logged into the Dashboard via a secure cookie.
_Avoid_: Auth Token, JWT, Login State

**API Key**:
A secret bearer credential generated by a User to authenticate client application requests to the Gateway.
_Avoid_: Token, Secret Key, Access Token

**Gateway**:
The unified proxy entry point that validates API Keys, enforces Rate Limits, dispatches requests to AI Providers, and records Request Logs.
_Avoid_: Proxy, Router, Server

**AI Provider**:
An upstream service or internal adapter responsible for executing model completions.
_Avoid_: LLM, Backend, Vendor

**Mock Provider**:
A built-in provider adapter that generates simulated chat completions and streaming chunks without external API dependencies.
_Avoid_: Fake Provider, Stub, Dummy

**Request Log**:
An immutable audit record of a single request processed by the Gateway, capturing model, token counts, latency, and status code.
_Avoid_: Event, Transaction, Usage History, Audit Trail

**Rate Limit**:
A sliding-window threshold restricting the maximum number of requests an API Key can execute within a one-minute window.
_Avoid_: Quota, Throttle, Cap
